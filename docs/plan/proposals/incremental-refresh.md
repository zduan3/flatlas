# 浅扫描与按目录 mtime 的增量刷新

> 状态：提案，未实现。当前完整扫描与 `--refresh-before` 的语义见 [扫描与目录汇总](../../design/scanning.md)。

## 背景

- 用户在外部删除若干条目后，只想确认这一层的删除，但当前只能递归扫描覆盖它的父目录。`--refresh-before` 无法表达“只重列这一层”：父目录的完成时间总是晚于其子目录（父目录在子目录全部处理后才完成），任何能让父目录重新枚举的 cutoff 都会同时选中它的子目录。
- 在大目录树上，即使使用 `--refresh-before`，每个需要刷新的目录仍要完整 readdir 并 stat 全部直接条目。

## 方案

### (a) 浅扫描

新增只重新枚举一个目录直接条目的扫描方式（例如 `scan PATH --depth 0` 或 `--shallow`）：stat 每个直接条目、upsert、推进该目录自身的 `self_completed_at_ns`，并在枚举无错误时确认其直接缺失条目及其已索引后代为 deleted；不进入子目录，子目录的汇总与 freshness 保持原值。

### (b) 按目录 mtime 的变化检测

刷新时先 stat 目录本身：目录 mtime/ctime 与上次成功枚举时记录的值相同时，跳过该目录的 readdir，只向下检查子目录。目录 mtime 只反映条目的增删改名，不反映已有文件的原地增长，因此需要周期性的完整刷新兜底。

## 语义与安全

- 浅扫描与 mtime 跳过都改变“被本次 scan 观察”的含义；跳过的条目不得被确认删除，也不能视为本次观测。
- (b) 会漏掉原地增长的文件，改变 coverage 语义：必须在 scan 记录中标明使用了变化检测，并让 freshness 与 `SCANNED-THROUGH` 不把跳过的目录表述为已完整观测。需要先完成设计评审。
- 只有 completed 的枚举才能确认删除；partial、failed、cancelled 仍不确认。
- 需要在 `directory_summary` 或 `path` 中保存上次成功枚举时的目录 mtime/ctime，需要向前 migration。

## 测试

- 浅扫描只确认直接缺失条目及其后代，不改变子目录的 freshness 与汇总。
- 目录 mtime 未变化时跳过 readdir；新增、删除、改名条目会改变目录 mtime 并被发现。
- 原地增长的文件在变化检测模式下不被发现，在完整刷新后被发现。
- 枚举错误时不确认任何删除。

## 待定

- 浅扫描的 CLI 形式，以及是否同样记录为独立 scan。
- 变化检测的默认开关、完整刷新周期与在 scan 记录中的表示方式。
- 不同文件系统上目录 mtime 精度与可靠性（含 Windows、网络文件系统）。
